# Ports

Ports is a navigation destination immediately above Repositories. Opening it refreshes accessible TCP listeners; Refresh repeats that inspection and the last successful refresh time appears directly below Refresh. Results are grouped by process, so one row can list several ports and bind addresses. The default view filters to the persisted list of ports/ranges (3000–3010, 4200, 4321, 5000–5010, 5173–5180, 5432, 6379, 8000–8010, 8080–8090, 9229, 27017). Users can edit the Ports list, restore defaults with Reset to default ports list, or show all accessible listeners. A delayed tooltip on reset lists the defaults. Invalid entries are reported and do not replace the saved setting. The Ports editor has extra spacing above it to distinguish it from the toolbar.

The Ports editor shows individual ports and ranges as removable, editable tags. Display ranges with a spaced em dash (for example, `3000 — 3010`); keep the persisted and plain-text value as `3000-3010`. Selecting a tag edits its value in place without hiding other tags; Escape cancels the edit, while leaving a valid edit commits it and returns to the read-only tag. Invalid drafts are discarded on blur. A range opens at its start, with Tab moving to the end and then committing the edit. A comma commits a port; a colon starts a range with the same start and end, and the range end can be adjusted without going below the start. Backspace in an empty entry removes the immediately preceding tag. After editing or removing a tag, users can enter another port. A toggle switches the editor to plain text for bulk changes. An empty state explains when no accessible processes match the selection.

The process list scrolls independently; the page controls stay fixed above it. Collapsed rows show the compact ports-and-command line followed by process name and PID. Expanded rows keep the ports-and-command line, replace the second summary line with a labeled detail list, and show one field per line for process, PID, owner, bind addresses, working directory, and start information. Long command lines wrap in the summary. Missing data is labeled unavailable; permission-restricted details are not guessed. Wildcard binds are called out as listening on all interfaces, with a note that network and firewall rules still affect reachability. A process may own multiple ports.

The danger icon button to the left of each process sends a graceful termination request to that process only. If the same process remains after five seconds, the app attempts a force stop. There is no confirmation. A stop is disabled when the app cannot obtain an identity suitable for guarding against PID reuse. Linux pins the process with a pidfd for both signals. macOS rechecks the kernel-reported process start identity immediately before each signal; macOS has no pidfd-equivalent conditional signal API, so a very small check-to-signal race cannot be eliminated there. Errors remain visible and users can refresh. Process command arguments are displayed locally only and must never be written to application logs.

Inspection runs without elevation and is limited by the operating system's visibility rules. It does not prove that an unlisted port is free. Workspace/repository association is omitted because listener cwd is not reliable evidence of ownership.
