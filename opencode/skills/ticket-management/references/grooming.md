# Grooming

Work collaboratively with the user to turn an idea into an approved, bounded
outcome. Keep unresolved material decisions visible; ask about one consequential
decision at a time. Record the outcome, scope, acceptance checks, non-goals,
validation, dependencies, and approval in the ticket when relevant. A ticket
stays `draft` while clarification or approval remains open; grooming does not
start implementation.

Distinguish the user-visible or engineering value from implementation machinery.
Use concrete observable behavior and evidence rather than capability labels.
Do not silently expand the approved boundary when implementation reveals new
decisions; record the discovery and return to the user for grooming.
