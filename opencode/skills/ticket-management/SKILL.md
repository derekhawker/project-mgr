# Ticket Management

Workspace tickets are Markdown files owned by the application, outside the
repository. The Markdown file is authoritative for status and work-session ID.
Use the applicable reference for the requested workflow.

## Route the request

- **Create or clarify:** read [capture](references/capture.md) and
  [ticket-format](references/ticket-format.md). Preserve uncertainty and create
  or refine a `draft`; a draft may continue to be clarified.
- **Groom:** read [grooming](references/grooming.md) and the format. Keep the
  ticket in `draft` while material decisions or approval are open.
- **Work, resume, or recover:** read [workflow](references/workflow.md) and
  [ticket-format](references/ticket-format.md). Read the canonical ticket before
  acting; use its recorded session when available.
- **Complete, cancel, or archive:** read [workflow](references/workflow.md)
  and [ticket-format](references/ticket-format.md).

Use the Workspace's canonical ticket directory supplied in session instructions;
never create tickets in the repository or infer ticket identity from the shared
repository or UI selection. Read the canonical Markdown for current content and
status.
